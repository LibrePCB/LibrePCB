# Plan: MCP Server for LibrePCB (`librepcb-mcp`, Python PoC)

Provides an MCP (Model Context Protocol) server which allows AI assistants
to work with LibrePCB, built as a *client* of the TCP RPC server (see
`dev/plans/rpc-server.md`, protocol v2). Since the RPC server speaks
MessagePack with EDA-typed payloads (opaque handles, nanometers,
microdegrees), the MCP server does value translation and provides a
higher-level API instead of a 1:1 bridge of the RPC protocol.

A Python implementation was chosen for the PoC. To avoid a third
hand-rolled protocol implementation (next to `dev/rpc-gui/client.py` and
`tests/ui/rpc/test_rpc_server.py`), the protocol client is extracted into
a shared library which both the rpc-gui and the MCP server use.

**Status:** In development (milestone 1).

### 2.1 API

```python
import librepcb_rpc

# The library is key-storage-agnostic: it never touches the filesystem.
# generate_keypair() creates an Ed25519 identity; client applications
# persist keypair.private_hex wherever they want (our own apps use a
# gitignored ".config.json" in their app directory).
keypair = librepcb_rpc.generate_keypair()

# connect(): TCP to the default port (19536) -> initialize (negotiated
# protocol version is verified against the generated PROTOCOL_VERSION)
# -> authenticate (sends the derived pubkey + the nonce proof). Raises
# the generated error classes on failure, e.g. RpcAccessDenied when the
# user denies the interactive connection request.
conn = librepcb_rpc.connect(name="librepcb-mcp", keypair=keypair)

# call(): positional arguments are mapped to the parameter order of the
# specification (the receiver handle is just argument #1 — the reserved
# "obj" key), keyword arguments by name. No manual dicts. Conflicts or
# too many positional arguments raise TypeError immediately; an unknown
# method with keyword arguments is passed through unchanged (forward
# compatibility), unknown + positional raises TypeError.
req = conn.call("SymbolInstance/add", schematic,
                component=..., gate=..., position=(10.0, 5.0))

# RpcRequest: chainable, no concurrent.futures compatibility. Callbacks
# fire on the reader thread (or, when registered after completion, on the
# registering thread); registering outcome callbacks after completion
# fires them immediately, so completions are never missed.
result = (req
          .on_progress(cb)     # fn(state): the reserved members
                               # (progress/step/steps/message), when present
          .on_data(cb)         # fn(chunk): only the NEW data of each message,
                               # including the final response's residual data
          .on_success(cb)      # fn(result): the final merged result
          .on_error(cb)        # fn(error): the RpcError
          .on_finished(cb)     # fn(outcome): result or error, exactly one
          .wait(timeout=120))  # -> result; raises RpcError / TimeoutError
req.done()                      # non-blocking poll
req.cancel()                    # -> [3, msgid]; completes exactly once
                                #    (RpcCancelled or the normal result)
```

### 2.2 Semantics

- **Rolling merge (streaming.py):** type-2 `result` fragments are merged
  into an internal state (maps recursively, arrays appended, everything
  else — including nil — overwritten, no deletion semantics); the final
  response payload merges into it as well. `on_data` receives the raw
  fragments (deltas) only; `wait()` returns the complete merged result.
  The invariant holds: all `on_data` chunks together merge into exactly
  what `wait()` returns. A nil response payload fires no `on_data`.
- **Exactly-once completion:** the reader thread ignores late or
  duplicate responses for a msgid; `cancel()` is a no-op when the request
  already completed.
- **Errors:** `errors.py` (generated from the spec's error section)
  defines `RpcError` plus one exception class per error code with the
  canonical message, and `error_from_response(code, payload)` which maps
  an error response to the matching class (unknown codes fall back to a
  plain `RpcError` with the code attached). Local failures use builtin
  exceptions: `TimeoutError` (local wait timeout; the request stays
  pending server-side — call `cancel()` in that case), `ConnectionError`
  (socket died, all pending requests fail), and `ProtocolVersionError`
  (the server negotiated a protocol version this client does not speak).
- **Threading:** one reader thread per connection; the msgid allocator
  and the socket writes are locked, so `call()` is safe from multiple
  threads (FastMCP runs sync tools in worker threads).
- **Key handling:** `connect(name, keypair)` performs the whole
  handshake; the client is identified by its pubkey, so each client
  application uses its own key (each key is confirmed once by the user).
  The library only provides `generate_keypair()`/`KeyPair` — where keys
  are stored is entirely up to the applications.

### 2.3 Generator integration

`rpc/gen.py` emits (committed, like all generated files):

- `dev/rpc-client/src/librepcb_rpc/api.py` — `PROTOCOL_VERSION`,
  `CLASSES` and `METHODS` (the parameter names of every method in
  specification order, keyed by the wire method name).
- `dev/rpc-client/src/librepcb_rpc/errors.py` — the error classes (see
  2.2).

The old generated `dev/rpc-gui/api.py` is dropped; rpc-gui takes an
editable path dependency on `librepcb-rpc` and imports the generated
module from there (`from librepcb_rpc import api`).

### 3.1 Session & connection lifecycle

- Connects to the library's default port (no port option for now; the
  instance-file discovery does not exist yet).
- Authenticates at startup as `librepcb-mcp` with a persistent keypair
  stored in a **gitignored `.config.json` in the app directory**
  (`dev/librepcb-mcp/.config.json`, created on first run; same pattern
  for rpc-gui later). First connection pops the interactive confirmation
  notification in the GUI; denied -> clean exit.
- Lazy auto-reconnect when the application was restarted; the session
  drops its handle caches then (handles die with the application).
- RPC errors map to readable MCP tool errors so the LLM can react (e.g.
  re-list after a stale handle).

### 3.2 Higher-level API (not a 1:1 bridge)

| RPC-level problem | MCP-level solution |
|---|---|
| Opaque handles (`obj`) | The session resolves projects/schematics by name, uuid, path or index; tools never expose handles. Recovery from `InvalidHandle`: re-list + retry once. |
| `ProjectEditor/set` requires all fields | `set_project_metadata` fetches the current values, merges the overrides and calls `set`. |
| `SymbolInstance/add` needs library UUIDs | `find_parts` (via `WorkspaceDb/query_sql`) returns ready-to-use identifier bundles; `add_symbol` accepts those or raw UUIDs. The LLM never writes SQL. |
| Units are nm / µdeg integers | LLM-facing floats in mm / degrees, converted in `convert.py`. |
| Rule-check message handles are transient | `run_rule_checks` stores them; `approve_rule_checks` approves by index, with a re-run hint when stale. |
| MCP cannot return binaries | `export_graphics` without a path returns the blob as MCP image content; with a path it writes files and returns the paths. |
| `WorkspaceDb` needs `wait()` after changes | `install_libraries` waits implicitly. |

### 3.3 PoC tool surface (~16 tools)

## 4. Testing

- **Library unit tests** (`dev/rpc-client/tests/`): an in-process mock
  msgpack server (socketpair-level) covers handshake & auth, version
  mismatch, positional/kwargs mapping, streaming merge + `on_data`
  deltas, progress, timeouts, cancel, error mapping and connection
  loss. Run with `uv --directory dev/rpc-client run pytest`.
- **Real application:** verified by hand with the MCP Inspector
  (`npx @modelcontextprotocol/inspector uv --directory dev/librepcb-mcp
  run librepcb-mcp`) against a running LibrePCB instance.

**ATTENTION:** For any manual test run, the application must be started
with `LIBREPCB_WORKSPACE=/home/ubuntu/tmp/LibrePCB-Workspace` — the
default (production) workspace must never be read or written.

1. **`dev/rpc-client/`** — `Connection`/`RpcRequest` (chainable),
   `generate_keypair()`, `connect()`, streaming merge; `rpc/gen.py`
   emits `api.py` + `errors.py` there; rpc-gui switches its `api`
   import (minimal change, full `client.py` port deferred). *Status: in
   progress.*
2. **MCP skeleton** — FastMCP, session (connect/auth/reconnect, key in
   gitignored `.config.json`), `get_workspace_info` +
   `list_open_projects`; Inspector check incl. the first-run approval
   notification.
3. **Project & undo tools** — handle resolution, `set` merge,
   save/close/undo/redo.
4. **Symbol tools** — `find_parts` (query_sql), `list_symbols`,
   `add_symbol`, `add_gate`.

6. **Graphics export** — file mode + image content mode.
7. **Workspace/libraries** — workspace info, `install_libraries` with
   implicit `WorkspaceDb/wait`.
